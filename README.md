# Keel · 龙骨

> **契约驱动的通用 B 端系统穿行测试框架** —— 让每一次业务迭代都有龙骨压舱。

**Keel** 为事务型业务系统（ERP / CRM / MES / WMS / TMS / HR…）提供统一的测试体系：以**机器可读的契约**为根，以**旅程穿行**为干，以**勾稽守恒**为原语，三通道（REST / MCP / UI）交叉验证。

它把真实 B 端系统的长期回归测试实践中沉淀的工程能力，提炼为可跨系统复用的框架——**财务只是起源案例，不是边界**。

## 为什么是"契约驱动"

测试体系最大的成本不是写断言，而是**口径考古**：接口字段靠逆向、错误语义靠猜、业务守恒律靠反推、环境漂移靠人眼。Keel 把这些都变成机器可读的契约，一次声明、三处消费：

```
┌────────────────────────────────────────────────────────┐
│ L5 报告层   发现→证据→建议 · 缺陷 saga · HTML 汇报       │
├────────────────────────────────────────────────────────┤
│ L4 旅程层   通用 9 段骨架: 越权→主数据守卫→档案→业务循环 │
│            →周期关账→报表勾稽→跨期承接→审计穿透         │
│            (每系统实例化 = 领域插件)                    │
├────────────────────────────────────────────────────────┤
│ L3 原语层   错误码语义 · 勾稽(diff=0/A=B/双向Δ) ·       │
│            状态机 · 幂等防重 · 基线四步管理             │
├────────────────────────────────────────────────────────┤
│ L2 通道层   REST · MCP · UI —— 同一断言多通道交叉       │
├────────────────────────────────────────────────────────┤
│ L1 契约层   六件套: openapi / error-codes / roles /     │
│            invariants / journeys / seed (+agent 契约)   │
└────────────────────────────────────────────────────────┘
```

骨架为什么通用？因为事务型系统的测试形态同构：

| 契约概念 | ERP/财务 | CRM | MES |
|---|---|---|---|
| 周期关账 | 月末结账/报出锁 | 业绩锁定 | 工单关闭/期间冻结 |
| 状态机守卫 | 闭期拒制单 | 线索已转化拒再转 | 批次已消耗拒冲销 |
| 守恒律 | 借贷平衡 | 回款≤合同额 | 投入=产出+损耗 |
| 勾稽 | 单据↔账↔实物↔税 | 商机↔合同↔回款↔业绩 | 工单↔报工↔库存↔质检 |

（技术型系统——中间件/协议栈/嵌入式——不适用此骨架，那是 chaos/性能框架的领地。）

## 组件选型（一期调研实战验证）

| 组件 | 角色 | 状态 |
|---|---|---|
| **Schemathesis** | REST 通道 fuzz/契约校验引擎（OpenAPI→正负例、links 状态化、custom checks 挂 invariants） | ✅ 实战验证：8 秒 42 case 发现 3 类真实参数校验缺陷 |
| **Playwright** | UI 通道基座（+官方 MCP agent 化路线） | ✅ 实战验证：11 断言全绿 21s |
| **pytest** | Python 测试基座（fixture/plugin） | 采纳 |
| testcontainers | 依赖环境编排（新系统开发期） | 按需 |
| e2e (TesterArmy) | UI agent runner（录制回放缓存独有） | 观察项 |
| Pact | 契约治理思想（Broker 版本化/验证矩阵/部署门禁） | 抄思想不用代码 |

## 契约的编写模式：AI 主笔、人主拍板、实测主校验

- **AI 执笔**（劳动量 90%）：领域模板、错误码穷举、代码考古、骨架迁移
- **人拍板**（决策量 10%）：私有口径决策——形式是"答 AI 的选择题"，不是从零写规则
- **实测校验**：AI 假设带证据锚定 → 真实系统验证 → 通过才入契约（`confirmed`），否则 `unsourced` 待拍板

契约进 git、同 PR 流转、CI 三道闸（schema 合法性 / 契约-实现一致性 / invariants 编译成断言）——**契约必须可执行，否则必然腐烂**。

## 路线

1. **qa-kit 抽包**（进行中）：起源项目的 python 断言资产 → 可复用内部库
2. **v0.1**：第一个新系统（CRM/MES）启动时落地五层架构，n=2 固化契约 schema
3. **agent 层**：模型 key 就绪后接入（playwright-mcp + LLM payload + 会话编排三路现成组件）
